### Q01 · bug · 高 —— 画一圈墙「点回起点」不会收口；接着点「完成」会把整条没收口的墙链悄悄丢掉
- 复现：新建空白户型 → 空状态卡「画外墙」→ 依次点矩形四个角 → 再点第一个角（用户画一圈墙的自然动作）→ 点右上「完成 Esc」。
- 期望：点回起点就闭合并结束（「柱子 / 墙块」工具就是这样）；或者至少「完成」先提交手上正在画的墙。
- 实际：点回起点只是又加了一个点，绘制还在继续（`drawPts` 5 个点，`effWalls()=0`）；点「完成」后 4 段墙全部消失，
  `effWalls()=0`，空状态卡又出现，没有任何提示，也不能撤销（这些墙从来没进过文档）。只有双击、回车或者「再点**末**点」才会提交。
  首次使用的引导恰好把人带进这条路径，S25 又把「完成」改成了琥珀色主按钮，更容易踩到。
- 证据：`work/qa/shots/s1c-loop.png`（闭合后还在画）、`s1c-done.png`（完成后空状态卡回来，墙为 0）；
  回车结束的对照组 `s1d-after.png`（walls=4，卡片消失，撤销 / 重做正常）。
- 代码：`app.html:7353-7366`（画墙只认「再点末点」，「回到起点就闭合」只给 `poly`）；`app.html:21834` `#wDone` → `setWallEdit(false)` → `invalidateEditLayer()`（`app.html:2153`）清掉 `drawPts`。
  切换工具（`app.html:21462`）也会同样丢掉。

### Q02 · bug · 高 —— 在检视面板里换着选对象，上一个对象的控件会留下来（死控件）
- 复现：改户型（或装修）→ 点一扇窗 → 再点一扇门；或者门 → 洁具。
- 期望：只显示门（或洁具）的控件。

  选中洁具以后，门和窗两组都还在。这些控件读的是 `winSelEnt()` / `selDoor()`，当前选中不是窗（或门）时它们返回 null，所以点了没反应。
  可见的 `*Ctl`：窗 → 门 = `doorCtl,winCtl`；接着点洁具 = `doorCtl, winCtl, fxCtl`。直接选门（之前什么都没选）只有 `doorCtl`，所以这是顺序相关的残留。装修分区一样。
- 证据：`work/qa/shots/s4a-door.png`（门的检视下面挂着整套窗控件）、`s4b-deco-win-door.png`；`s4a.mjs` / `s4b.mjs` 的输出。
- 代码：`app.html:6837-6857` `updateWallBarFromSel_()`：洁具分支在 `ctxOn('#doorCtl', …)` 之前就 `return`，门分支在 `ctxOn('#winCtl', …)` 之前就 `return`。
  以前这些控件叠放在工具条的 `#ctxSlot` 网格里，残留的大概被盖住了；搬进纵向排列的检视面板后就露出来了（推断）。

## 备注（不算 bug）
- 窗帘下拉 `#wWinCurtainSel` 是靠「循环点击影子按钮直到款式一致」实现的，而 `_shadows` 刷新时会用当前款式覆盖下拉的值，**除非下拉正有焦点**。
  真实用户选选项时下拉有焦点，所以结果是对的（实测逐档都对）；但如果没有焦点就派发 change（比如自动化、读屏软件），只会走一档（`app.html:21937-21942`）。属于健壮性隐患。
- `#totals` 的悬停提示里写了「4 件带 * = 加拿大在售的是另一配置」，清单行里没看到 `*` 标记（没细查）。
