# ADR-0006: 产品调性 —— 面向 homeowner 的「快速形成概念」工具

- 日期：2026-09-17
- 状态：accepted
- 决定者：用户（项目所有人）
- 关联：ADR-0001（命名/产品身份）、ADR-0003（输入通道）、ADR-0004（单文件）

## Context

在定义 UI 验收标准时暴露出一个必须先定的北极星：**这个软件给谁用、我们帮用户省的是
哪段时间**。不定这个，计划会漂移成两种坏东西之一：pro 工具（密度高、功能堆、
像 AutoCAD）或 consumer toy（浅、没精度）。

## Decision

**MiniDen = 给 homeowner（普通用户）快速形成「我家」概念的规划工具
（布局 / 放不放得下 / 氛围）。**

### 1. 对象

普通用户 / homeowner：给自己家做简单设计与规划。**不是专业设计工具**——
专业人员用 AutoCAD / Unreal Engine 5 这类工具保证绝对质量，MiniDen 不在那个轴上竞争。

### 2. 「快捷」的定义：time-to-insight，不是原始性能

Speed first-class **≠「app 必须跑得飞快」**。正确定义是：
**不在「建模」和「获得初步印象 / 家庭规划概念」这两件事上耽误用户太多时间。**

- **用户永远不建模**：家具库是我们预先建模好的（用户只拖放）；户型是
  「机器出初稿 + 轻修正」。反例 = AutoCAD：可以精细建模，但用户要为一个
  沙发画几小时的线——MiniDen 省掉的就是这段。
- **初步印象以分钟计**：从「打开」到「看到我家摆完家具大概什么样」
  （娃娃屋 / 第一人称 + 昼夜）应是几分钟，不是几小时。
- **边界（用户原例）**：像「楼梯每一节台阶相对自己的箱体向前突出多少」
  这种特别细节的装修问题 = 施工图域，**MiniDen 不做**。
- 技术性能（启动/帧率/解析时长）是快捷的**子属性**（体验手段，不是定义）。
  顶层 SLO 用**用户时间**表述（roadmap E14/E17）；
  技术指标是它的子指标。

### 3. 可扩展：代码优先，AI skill 是交付物但不是依赖

- `add-catalog-item` skill **是我们打算 deliver 的东西之一**（留在 repo，README 说明）
- 但系统**不依赖外部 AI**：功能全部代码化；**运行时零 AI 调用**；
  目录增长 = 稳定协议（JSON schema + model API + check-item CLI），
  任何人或任何工具都能用它扩展（AI skill 是同一协议上的便利层）

### 4. 在这个范围内，尽可能提高精细度、准确度、可用度

- **决策级精度，不是图纸级精度**：真实尺寸 / 真实双币价格 / 碰撞 / 测量 /
  窗洞 / 昼夜氛围——都服务于「放不放得下、好不好看、够不够亮」
- consumer 级的简单 + 决策级的精准 = 差异化（竞品要么 pro 而精、要么 consumer 而浅）

### 5. 明确不做（调性划定）

- BIM / 施工图 / 结构校核 / 毫米级安装细节（楼梯台阶突出量那类）
- 专业协作（多用户实时）、参数化家具
- 照片级作为**默认**视图（PT 保持 opt-in：它是「出最终照片」的工具，不是概念工具）
- 通用 3D 内容创作

## Consequences（计划校准，见 roadmap.md）

- **E14/E17 SLO 重新定位**：顶层 = 用户时间 SLO
  （首次 ≤3 分钟：打开→放家具→3D 印象；导入路径：上传→可用初稿 ≤3 分钟）；
  技术指标（启动 <1.5s、切视图 <300ms、DXF 10MB <3s 带进度）是子指标
- **S5/S6/S7**：「机器出初稿」是快捷的主要体现——导入的产出必须是
  *立即可用*的状态（单位自动检测 + 一次确认），不是解析出的原始数据
- **S2（窗）/ S4a（昼夜）优先**：都直接影响「概念」（采光、氛围）
- **S8 ML 降为 v2+**：调性 = 快捷；ML 重，仅当 P0–P2 覆盖不足
- **新增 S10：目录扩展协议**（第 3 条的代码化）
- R9 增渐进披露（日常操作表层 / pro 操作第二层）
- R10 D.2 增对象判据：「没看过文档的第一次使用者能完成吗？」

## Alternatives considered

- **pro 工具定位**（酷家乐/Blender 式）：拒绝——用户与价值锚点不同
  （time-to-insight vs 绝对精度）；会稀释「快捷」
- **consumer toy**（纯拖放、无精度）：拒绝——用户明确要求 consumer 范围内
  精度拉满；且我们的户型精度是护城河不是负担
- 「性能型快捷」（把 speed 只理解为 frame rate / 启动速度）：拒绝——
  那是子属性；用户省的是建模与形成概念的时间
