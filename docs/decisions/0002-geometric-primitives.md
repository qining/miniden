# 0002. 几何原语是存储，近似只在消费端

- 日期：2026-07-17
- 状态：已接受（用户拍板，硬要求）

## 背景

Project 文档（ADR-0005）需要表达弧墙、圆窗、圆柱、门扇摆幅等曲线。
两条路：(a) 存储层用折线近似（简单，所有消费端无差别）；
(b) 存储真原语（seg/arc/polygon），消费端各自展开。
折线近似入库会**永久性丢失曲率信息**——半径 2m 的弧用 8 段折线存，
将来想做 SVG path `A` 命令原生渲染、3D 圆环挤出、精确弧长量尺寸，
都拿不到真值，只能重新猜测。

## 决策

1. 存储层**必须**是真原语：`seg(x1,y1,x2,y2)` / `arc(cx,cy,r,a0,a1,dir)`
   （`a1-a0=360°` 即整圆）/ `polygon([pts])`
2. 所有消费端统一调用**唯一的** `expand(geom) → 线段链` 函数，
   每端自带粒度参数（2D 吸附要密、缩略图可以稀）
3. 允许消费端**跳过 expand** 走原生曲线：SVG `path A`、3D 圆柱/圆环几何体、
   解析弧长
4. 弧的编辑交互 = 两点 + 一个方向点（三点定弧）
5. CV/ML 检测输出直接是原语（Hough → seg，HoughCircles → 整圆，
   边缘拟合 → arc），不在中间层降级成折线

## 后果

- `expand()` 是纯函数 → vitest 单测覆盖（采样数 vs 弦高的误差断言）
- 2D/3D/CV 三端共享同一展开函数，行为一致
- 代价：比「折线入库」多一层间接；换来的是文档无损 + 原生曲线可用
