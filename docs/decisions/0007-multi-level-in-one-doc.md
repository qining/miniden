# ADR-0007: 多层 = 一份户型文档里的若干楼层；当前层换进文档顶层

- 日期：2026-10-22
- 状态：accepted
- 决定者：Board（主会话），依据用户 2026-10-22「对于 house 来说，多层以及楼梯，这个需求也非常要命」
- 关联：ADR-0005（Project schema v1）、ADR-0006（调性）、E26（多户型注册表）、`docs/design/home-v2.md` §S17

## Context

到目前为止一份户型就是一个平面：`ProjectDoc` 顶层的 `walls / windows / doors / solids / rooms / fixtures / runs / outlets`
就是「这套房子」。代码里读这些数组的地方超过 100 处（`DOC.walls`、`effWalls()` → `docToLegacy(DOC)`、
`floorPts()`、`buildStatic3D` …），撤销快照、存档、导出、多户型切换都按「一份文档 = 一个平面」写。

house 需要：好几层叠在一起、楼梯连接上下层、每层有自己的墙与家具、3D 里能看到整栋楼。

## Options

| 方案 | 做法 | 否决 / 采用理由 |
|---|---|---|
| A. 每层一份户型（复用 E26 注册表，加「同一栋」分组） | 切层 = 切户型 | **否**：3D 叠层要同时载入别的户型文档，而建 3D 的代码依赖一大批「当前户型」的全局量（`PLAN`、`DOC`、`PLAN_ID`…）；家具、撤销环、导出被拆到好几份存档里，「整栋导出」「撤销一步」都要跨存档拼；楼梯要跨文档引用 |
| B. 文档里存 `levels[]`，所有消费端改成「按楼层取」 | 100+ 处 `DOC.xxx` 全改成 `L().xxx` | **否**：爆炸半径太大，每一处都可能漏 —— 这正是前三十轮 bug 猎反复钓到的那类「漏一条路径」 |
| **C. 文档里存 `levels[]`；当前层的内容换进顶层，其余层的内容存在各自的 `levels[i]` 里** | 切层 = 把顶层数组换出去、把目标层换进来 | **采用**：现有编辑 / 绘制 / 3D 代码一行不改就作用于当前层；存档 / 导出 / 撤销快照仍是「整份 `DOC` 的 JSON」，自然包含所有楼层与「当前是哪一层」；只有真正需要「所有楼层」的地方（3D 叠层、整图重标定、校验、合计）才显式遍历 |

## Decision

1. **数据形态**：`ProjectDoc.levels?: Level[]`（按标高从下到上）+ `ProjectDoc.level?: string`（当前层 id）。
   当前层在 `levels[]` 里只留「外壳」（`id / name / elev`），它的内容（`LEVEL_KEYS`：墙、窗、门、柱、房间、洁具、台面、点位、楼梯、
   地板轮廓、底图、阳台、隐藏表、层高、整层地板）在文档顶层；其余层的内容在各自的 `levels[i]` 里。
   **没有 `levels` 的文档 = 单层**，与今天逐字节一致（`#calib`、黄金截图、所有旧存档都不动）。
2. **只有自包含户型（新建空白 / 导入）能加楼层。** 内置户型的专属构件（厨房块、中岛、阳台补板、落地窗带、房间名常量、
   `FLOORPTS`、`hidden` 表、「重置内置」）全部绑在那一层上；让它也能多层，要在十几处加「是不是底层」的门控，换来的只是
   「公寓也能叠一层」这个没人要的能力。界面如实说明：「内置户型是单层公寓；做多层的房子请新建空白户型或导入图纸」。
3. **标高**：第一次加楼层时，原有内容成为 `lv1`（标高 0）。往上加一层：标高 = 下一层标高 + 下一层层高 + 楼板厚（缺省 1ft）；
   往下加（地下室）同理。改层高后整栋重排标高，`lv1` 永远在 0。
4. **家具带楼层标记** `it.lv`（缺 = `lv1`）：2D 只画当前层、碰撞只在同层判、3D 按所在层的标高摆、合计与采购清单覆盖全部楼层（一栋房子一张单）。
5. **楼梯属于它起步的那一层**（`stairs[]` 是楼层内容），升到上一层；上一层的楼板在楼梯占地处开洞，2D 在上一层画虚线轮廓 +「下」。
6. **3D**：每层一个静态组放在自己的标高上；娃娃屋显示「当前层及以下」（俯瞰要看得见当前层），室内显示全部（从楼梯口能看见另一层）。
7. **切层不是一次编辑**：不进撤销环；但 `DOC.level` 在快照里，撤销会把视图带回改动发生的那一层。切层时作废编辑层（`invalidateEditLayer`）与量尺寸标注（它们属于上一层的几何）。
8. **需要「全部楼层」的消费端必须显式遍历**：`validate`（每层都校验）、整图重标定（每层都缩放，否则楼层错位）、3D 叠层、合计、
   目录包移除提示里的件数（家具已在同一个 `state.items` 里）、导入布局（楼层标记对不上的件落到当前层并说明）。

## Consequences

- 新增的「挂在楼层上」的实体（楼梯、房间地板）直接放进 `LEVEL_KEYS`，切层自动带上。
- 任何「遍历文档几何」的新代码都要先问：它要的是当前层，还是所有楼层？（`docs/design/architecture.md` 不变量 #23）
- `levels` 的纯函数（启用、切层、加 / 删层、标高重排、逐层遍历）在 `src/schema/levels.ts`，vitest 守着；
  app 侧只做「换完之后刷新视图」。
