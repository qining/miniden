## 0. 总评：最大的 5 个结构性问题

1. **整个功能架构是按「数据对象」分的，不是按「房主要做的事」分的。** 「编辑墙体」这一个模式里装了 10 个工具（墙、柱、门、窗、洁具、台面、楼梯、房间/地板/墙色/窗帘、点位……），其中跟墙有关的只有 3 个。房主想做的「换地板 / 刷墙色 / 挂窗帘」是**装修外观**层面的决定，跟「改户型结构」在心智上完全是两回事，现在却锁在同一个叫「编辑墙体」的入口后面，还要再进一层「房间」工具才看得到（X01、X02）。产品负责人的两条观察都对，而且是这个根问题的两个表现。

2. **「改外观」的反馈闭环是断的：只能在 2D 改，只能在 3D 看。** 地板、墙色、窗帘、窗框、门色只有 2D 编辑模式下的工具条能改；但它们的效果在 2D 几乎看不出来（墙色和窗帘完全看不到，地板被暗色主题压成灰棕）。切到 3D 后，「编辑墙体」按钮还亮着，工具条却消失了，目录和清单还处于禁用的灰色状态——用户被卡在一个看不见也操作不了的模式里（X03、X26）。核心承诺是「看起来怎样」，这条路径恰恰最费劲。

3. **同一类东西散在好几处，选中后的属性也分两个地方显示。** 家具属性在右侧面板；墙/门/窗/房间的属性在顶部工具条（这时右侧面板写着「未选中家具」，还是灰的）。固定灯具在家具目录里，洁具、台面、冰箱模块却在编辑模式里，冰箱在目录里还有一份。窗帘既能在「窗」里设，也能在「房间」里设。户型、楼层、方案三层容器分别放在「工具 ⌄」第二层、画布左上、画布右上（X04、X08、X23、X24）。

4. **层级的权重分配和使用频率是反的。** 设置级的东西放在顶层，而且很显眼：cm/英尺 用琥珀色高亮、汇率输入框、3D 的 11 个场景氛围按钮。高频和关键的东西反而藏得深：换户型在「工具 ⌄」里，换地板要 4 层，没有保存状态，导出备份要两个文件。危险操作常驻在工具条上：「重置内置」「整图按此缩放」（X07、X08、X17、X18、X33、X40）。

5. **用词偏开发者和施工方，同一概念叫法也不统一。** 比如「实墙 / 门洞 / 开口」「端点：整体」「画柱/异形」「点位」「特征线（Canny+Hough）」「ProjectDoc JSON」「À-Trous 保边滤波」「items 数组 / uid」。「布局」和「方案」指的是同一件事；「采购清单」其实是「已摆家具列表」，行尾的 ✕ 会把家具从平面图上删掉。切换按钮的文字有时表示当前状态，有时表示点下去的动作（X10、X11、X27、X28、X31）。

## 2. 建议的新信息架构（草图）

### 2.1 原则
- **按房主的任务分区**，不按数据结构分：结构（很少改）→ 装修外观（偶尔改、要边改边看）→ 摆家具（最常用）→ 清单（交付物）。
- **一个检视面板**：选中任何东西（家具、墙、窗、门、房间、地板、洁具），属性都出现在右侧同一个位置，在 2D 和 3D 里都能用。
- **只有结构编辑才需要真正的「模式」**（画线时点击的含义变了）；外观属性靠「点它 → 改它」，不进模式。
- 设置级、低频、危险的东西往下沉；顶栏在三个视图下布局一致。

**各分区放什么**

| 分区 | 功能 | 现在在哪 |
|---|---|---|
| 摆家具（缺省） | 目录、搜索 / 分类 / 尺寸筛选、自定义家具、多选、复制粘贴、方案切换 | 左侧目录 + 画布右上方案 |
| 装修 | 全屋 / 各房间地板（色块）、墙色、窗帘、窗框 / 玻璃 / 窗款式、门的颜色、洁具、橱柜台面与模块、固定灯具、内置家电 | 散在：编辑墙体 → 房间 / 加窗 / 选中门 / 洁具 / 台面；固定灯在家具目录 |

| 清单 | 合并后的采购清单、地板用量、复制 / CSV、币种 | 右侧面板下半部分 |
| 户型 › 楼层 › 方案 | 一条面包屑，每段是一个下拉 | 工具 ⌄ / 画布左上 / 画布右上 |

在「装修」分区里，2D 和 3D 都能点地板或墙来选中；「改户型」分区进入时如果在 3D，提示「结构编辑在 2D」并提供一键切换，而不是静默强切。

### 2.3 「编辑墙体」改叫什么

推荐**拆成两个**：

| 方案 | 命名 | 理由 | 风险 |
|---|---|---|---|
| ★ A：拆分 | 「**改户型**」（结构）＋「**装修**」（外观） | 和房主的两种意图一一对应：「房子本身长什么样」与「表面用什么材料」。「装修」是中文家居语境里人人都懂的词，能涵盖地板、墙色、窗帘、洁具、橱柜；「改户型」比「编辑墙体」宽，包括门窗开洞、楼梯、楼层 | 「装修」也可能被理解成整个施工过程；可以用副标题「地板 · 墙色 · 窗帘 · 洁具」锚定 |
| B：保留一个模式 | 「**户型与装修**」 | 改动最小，名字至少覆盖了现在模式里的全部内容 | 名字长；没解决「改外观也要进结构模式」和 3D 不可用的问题 |
| C：保留一个模式 | 「**硬装**」 | 行业里对「结构 + 固定装修」的标准说法，和「软装（家具）」成对 | 对非装修圈的用户偏行话；墙体结构算不算「硬装」也有歧义 |

不推荐的名字：「编辑模式」（太泛）、「施工」（和产品「不做施工」的定位冲突）、「建模」（偏技术）。

## 5. 综合整理：工程裁决与工作包（2026-10-28，主工程）

> 审阅报告（§0–§4）原样保留，作为 UX 组复核时逐条对照的基线。下面是采纳与否、怎么分包、按什么顺序做。
> 抽查过证据：X01 / X05 / X03 截图与代码对得上（例：选中门时 `#wType` 仍显示「实墙」）。

### 5.1 结论

UX 组的根判断成立：功能按「数据对象」分，不按「房主要做的事」分；「编辑墙体」一个模式装了结构 + 外观两类意图。
采纳 §2 的新信息架构为目标形态，分 5 个工作包落地。**IA 与视觉一起改**（先由 UI 组出 facelift 规格，再实现），
否则先挪位置、再改样子会把同一批断言改两遍。

### 5.2 工作包

| 包 | 内容 | 覆盖 |
|---|---|---|
| **F1 分区与模式** | 顶栏三分区「摆家具｜装修｜改户型」（替代「编辑墙体」）：「改户型」= 结构工具（画墙 / 门 / 窗 / 柱 / 房间轮廓 / 楼梯 / 更多▾ 点位·台面），只在 2D；「装修」= 外观（全屋 / 各房间地板、墙色、窗帘、门窗外观、洁具、台面），**2D 与 3D 都可用**（选中状态与检视面板在 3D 里保留，改了当场看）。进「改户型」时在 3D → 明确提示 + 一键回 2D，不静默强切；模式条常驻主按钮「完成（Esc）」；危险 / 罕用（重置内置、整图缩放、删除所选）收进「⋯」；两侧面板在「改户型」里不再整列灰着占地方 | X01 X02 X03 X06 X07 X21(部分) X22 X29 X44 X46 |

### 5.3 不在这一轮做 / 改了做法的

- **X36 同款不同色合并成一张卡**：目录数据里没有「同系列」字段，靠名字前缀猜会误合并（不同款同系列名的很多）。这一轮只做分类芯片；
  合并需要先给目录条目补 `family` 字段（数据工作，走 add-catalog-item 流程），记为候选。
- **X35 目录商品也能改颜色**：保留（房主拿它试配色），但标签改成「显示颜色（只改画面，不改买的款式）」，清单不受影响——属于 F5 文案。
- **X21 摆家具模式里点墙 / 地板**：点地板 = 选中这个房间并打开「装修」检视面板里的地板（不进结构模式）；点墙 / 窗在摆家具模式里仍不选中
  （摆家具时误选墙会挡住拖家具），检视面板空状态提示「改地板 / 墙色 → 装修；改墙 → 改户型」。
- **3D 里直接点墙 / 地面选中**（X03 的推荐方案的后半）：这一轮做到「装修的选中与检视面板在 3D 里可用」；3D 射线点选建筑构件记为候选。

### 5.4 约束（给 UI / 工程）

- `#calib` md5 不变（`body.calib` 锁旧版侧栏宽度；顶栏高度在 calib 视图不能变）；黄金截图态（ui-gate）改了就显式重拍并量差异；
- 元素 id 与事件处理器尽量不动（bench 523 + 234 + 259 条断言、E2E 41 条流程靠它们）；文字 / 位置改动后受影响的断言按新口径改写并在提交里写明；
- 单文件、暗色主题、现有 CSS 变量；笔记本宽度（1280 / 1440）三个视图都不折行、不溢出。
