# 15 · 装修材料库大扩展：需求与范围研究（S26，UX 专家组）

> 触发：用户 2026-10-29：「认真拓展一下装修对应的材料库，比如墙面、颜色、洗手池的样式、地面的样式、窗户的样式，类似这些，进行一轮大的扩展。」
> 视角：信息架构 / 交互 / 视觉层级 / 文案与术语 / 新手可发现性，五个视角合成一份。只读研究，没有改 app.html。
> 判据仍是 ADR-0006：**帮房主回答「放哪 / 放不放得下 / 看起来怎样」，做到决策级精度，不做施工图**。
> 截图：`work/ux/shots/s26/`；现状数字都来自 `dist/app.html`（1729325 构建）的真实操作和源码。

## 0. 摘要

**这一轮的定位**：「装修」分区现在能选的东西太少：地板 20 种、墙色 12 种、洁具每类只有 1 种样子、门 2 种颜色，台面、天花、踢脚线完全不能选。房主在 3D 里看到的始终是「同一套白盒子」。这一轮要做的是：把房主在建材市场、家居店里真实会面对的选择，以**有限而有代表性**的程序化预设补齐；同时把选择器从「一面铺开的色块墙」改成「按对象查看当前材质 → 打开选择器挑」，否则数量一多界面就撑不住了（§3）。

| 级别 | 内容（细节见 §1） |
|---|---|
| **P0**（这一轮必须做） | ① 墙色体系 12 → 约 42 色，按色系分组；② **单面强调墙**；③ **墙砖**（卫浴、厨房：满铺 / 半高 / 防溅区）；④ 地面 20 → 约 40 种，加铺法「错缝」；⑤ **洗手台 / 浴室柜 5 种形式**，含常用宽度和柜体颜色；⑥ 马桶 3 种形式；⑦ 淋浴 5 种形式；⑧ 浴缸 2 种形式；⑨ 门颜色 2 → 8 种，门板样式 5 种；⑩ 橱柜柜门颜色 + 台面材质 + 门板 3 种样式；⑪ **材质选择器**（分类芯片、搜索、**最近用过**、**这套房子已用**，悬停预览）——没有它，前十项就没法用 |
| **P1**（下一步做） | 墙纸（8 种程序化图案）、护墙板 / 墙裙、踢脚线、天花颜色、**每个房间一种五金色**、窗格、百叶 / 罗马帘、窗帘色板、厨房吊柜（含双色柜）、镜子形状 / 镜柜、淋浴玻璃与边框、马桶圆形 / 加长型、**整屋配色方案**（6 套）、**在 3D 里直接点选**地面、墙面、天花、洁具、门窗、2D 装修模式下的墙面色带、**用量估算**（涂料 / 墙纸 / 墙砖，不计价）、吸管（复制材质） |
| **P2**（记为候选） | 石膏线 / 顶角线、天花木饰面、文化石 / 砖墙、艺术漆 / 微水泥墙、漆面光泽、门把手样式、门套 / 窗套 / 窗台板颜色、隐形门、竹 / 软木地板、拼块地毯、过门石、爪脚浴缸、角缸、长虹玻璃、**装修外观跟着方案走**（同一户型比较两套配色） |

**信息架构的核心建议**（§2）：
1. **对象优先**：在 2D、3D 里点一个东西，或在左栏点一个房间 → 检视面板只列这个对象的几项「材质行」（缩略图 + 名字 + 规格 ▸）。点一行 → 打开**材质选择器**：在左栏位置展开一块宽面板，带分类芯片、色调筛选、搜索、「最近用过」「这套房子已用」，悬停就在画布上实时预览，点一下才确定，Esc 撤回。以后不再在检视面板里把 20～40 个色块整片铺开。
2. **墙面分两层**：「整个房间」是缺省，**单面墙是对房间的覆盖**。在装修里点墙面靠房间的一侧 = 选中这面墙（现在装修里墙点不中）；面板写明「跟房间 / 单独设置」，可以一键清除覆盖。
3. **整屋配色方案**放在「全屋」卡上，一键套用；可以选「覆盖所有房间」或者「只填没设过的」，整个套用算一步撤销。
4. **3D 里点选**升到 P1 第一位：材料的效果只在 3D 里看得到，「在哪看就在哪改」。
5. 2D 只用墙面色带和房间行里的小色块来提示「这里设过什么」，不去模拟墙纸、墙砖的图案。

**这一轮不做**（§4）：真实品牌色号 / SKU、外部图片和照片贴图、用户上传材质、AI 配色、铺贴排版 / 损耗 / 美缝宽度等施工参数、跌级吊顶和造型线条设计器、定制柜体内部格局、建材计价、窗户型材与玻璃性能参数。

## 2. 材料库范围清单（按「装修」里的对象分组）

**怎么读**：
- 「外观」= 属于装修，不改占地和结构，只换样子；
- 「外观 + 占地」= 属于装修（这类对象本来就在装修的「房子自带」里），但换样式会改变占地尺寸，要重新做碰撞检查，并在提示里说明尺寸变了；
- 「结构」= 属于改户型。

尺寸同时给中国大陆和北美的常见规格（应用已经有 cm / 英尺切换，个人户型在北美）。名字一律用通用名，不用品牌色号或商品名。

### 2.1 颜色体系（墙漆，也是门、柜、窗帘等「纯色」选项的公共色板）

**做法**：
- 用一套**公共色板**，按色系分 9 组，每组从浅到深排；墙、门、柜体、窗帘、踢脚线都从这套色板里取（每个对象可以只显示其中一部分）。
- 「自定义」保留，但放到最后一格，并且自定义过的颜色会进「最近用过」。
- 色值参考近几年主流涂料品牌热门色系里常见的「色相 + 明度」区间，**只取颜色值和通用名，不用任何品牌色号**。

### 2.7 洗手台 / 浴室柜

### 2.13 外观和结构的分界（汇总）

- **装修（外观）**：
  - 所有颜色、材质、样式：墙漆、墙纸、墙砖、护墙板、踢脚线、天花颜色、地面材质和铺法；
  - 门的颜色、门板、把手；窗格、框色、玻璃、帘子；
  - 柜门、台面、把手；五金色；
  - 洁具的**形式和尺寸档**（会改变占地，但洁具本来就在装修的「房子自带」里，改了要重新做碰撞，并在提示里说明尺寸变了）。
- **改户型（结构）**：
  - 墙的位置和厚度、门窗的尺寸和位置、开向、窗台高、飘窗；
  - 房间范围（包括「一套房子里两种地面」）；层高；
  - 壁挂马桶的假墙、壁龛、口袋门的门槽；吊顶高度。
- **判据**：改了之后墙线要不要动？要动就是结构。

| 设计点 | 建议 | 理由 |
|---|---|---|
| **对象优先 + 选择器** | 检视面板只列「材质行」（缩略图 + 名字 + 规格 ▸），**不再整片铺开色块**；点一行 → 左栏换成选择器（宽约 340px，1280 宽下也比检视面板宽） | 解决 a、b、c；检视面板始终在一屏之内 |
| **悬停预览** | 鼠标停在一个材质上，2D 和 3D 立刻临时换上；移开就恢复；点一下才写入文档（只占一步撤销） | 「看起来怎样」是这个分区的核心；比「点 → 看 → 撤销」快得多 |
| **最近用过 / 这套房子已用**（P0） | 选择器顶部两排；「已用」按出现次数排序 | 最常见的需求是「厨房和卫生间用同一种砖」「门和柜子同色」 |
| **分类、色调、搜索** | 分类芯片（第一层）+ 浅中深 / 暖冷（第二层）+ 搜索（匹配名字、规格和同义词：「白」能搜到暖白、米白；「60」能搜到 60×60 / 60×120） | 40 种以上就需要第二层筛选 |
| **单面墙**（P0） | 装修的「选择」：点在**墙内侧 30cm 以内** = 选中这面墙（房间那一侧）；点房间中部 = 选中房间。悬停时预先高亮将被选中的对象。墙面面板写「跟房间（雾蓝）/ 单独设置」，可一键「清除单独设置」 | 解决 e；单面墙是对房间的覆盖，房间设置仍是主路径 |
| **墙面的数据身份** | 单面墙按「房间 + 这条墙线（端点 + 法线，共线判定）」存，**不能按墙段 id 存**：开一扇窗会把墙拆成三段，按 id 存的话强调色就丢了 | 实现风险，先写在这里 |
| **2D 墙面色带**（P1） | 装修模式下，在每面墙的房间一侧画一条 5–6px 的色带（墙砖加细斜线）；calib 视图和摆家具模式不画 | 解决 f |
| **3D 点选**（P1 第一位） | 在装修里，3D 点地面 = 房间，点墙内侧 = 这面墙，点天花（室内视角）= 这个房间的天花，点洁具 / 门窗 / 柜子 = 对象；悬停描边 | 解决 g；材质的效果只在 3D 看得到 |
| **整屋配色**（P1） | 放在左栏顶部「整屋配色 ▸」；进入后是 6 张方案卡（2×3 缩略效果图），悬停预览，点了以后选范围和覆盖方式 | 降低「从零开始选几十项」的门槛 |
| **房间行摘要** | 左栏每个房间行显示 3 个小色块：地面 / 墙 / 踢脚线或墙砖 | 一眼看出哪些房间设过 |
| **洁具面板** | 选中洁具：形式（分段或带图标的列表）、尺寸档（分段）、颜色和台面（材质行）；**「类型」下拉从已放好的洁具面板里移走**（改类型 = 删掉再放），只留在「放洁具 · 下一个」卡里 | 解决 d |
| **用量估算**（P1） | 清单里的「地板用量」扩展为「装修用量」：涂料按面积 ÷ 每升 10m² × 2 遍；墙纸按卷（大陆约 5.3m² / 卷）；墙砖按面积。都标「不含损耗、不计价」 | 决策级的数字，不进施工域 |
| **装修跟方案走**（P2，建议列为下一轮的研究题） | 方案除了家具之外，再存一份「外观覆盖」（地面、墙、门、柜的选择）；结构仍然共用 | 解决 h。数据改动大，涉及撤销、清单、导入导出，需要单独评估 |
| **命名** | 只用通用名，加规格副标题（「白色地铁砖 7.5×15 · 错缝」）；不用品牌色号 | — |
| **calib** | 所有新增的 2D 视觉元素都走 `!CALIB` 分支；3D 材质不进 calib 视图 | 约束 |

## 4. 这一轮明确不做

| 不做 | 理由 |
|---|---|
| 真实品牌色号、商品 SKU、建材价格 | 商标和数据维护问题；运行时不联网；建材价格差异太大，算进合计会误导（清单只给用量） |
| 外部图片、照片贴图、扫描材质 | 单文件、离线的约束；体积 |
| 用户上传自己的材质照片 | 图片要存进文档，体积和隐私都是问题；先用公共色板加自定义色顶替 |
| AI 配色、风格推荐 | 运行时不调 AI（ADR-0006 §3）；用整屋配色方案顶替 |
| 铺贴排版、切砖、损耗精算、美缝宽度、找平、防水、龙骨、水电走线 | 施工图域（ADR-0006 §5） |
| 跌级吊顶、灯槽、造型线条、护墙板自定义造型设计器 | 偏设计 / 施工，超出「简单规划」的范围 |
| 定制柜体内部格局（抽屉、拉篮）、台面厚度 | 定制设计域 |
| 窗户型材系列、Low-E / 中空玻璃参数 | 性能 / 施工参数，对「看起来怎样」没有影响 |
| 单块砖编辑、拼花设计器 | 工具成本高，用户少 |
| 第二套户型级「材质库」的导入 / 导出 | 现在的目录扩展包协议只覆盖家具；材质包可以以后按同一协议扩展 |

## 5. 体积与性能估算（要不要上调预算，理由是什么）

| 项 | 估算 |
|---|---|
| 数据（42 色、约 40 种地面、墙砖 8 种、墙纸 8 种、门 / 柜 / 台面 / 五金的预设、6 套配色方案） | 约 15–25KB |
| 程序化贴图生成器（墙砖 4 种铺法、墙纸 8 种图案、新地面铺法：错缝、花砖、赤陶、洞石） | 约 30–50KB |
| 3D 建模函数（洗手台 5 种形式、马桶 3、淋浴 5、浴缸 2、门板 5、柜门 3、踢脚线 / 护墙板） | 约 50–80KB |
| 界面（选择器、单面墙选中、2D 色带、方案卡） | 约 20–30KB |
| **合计** | **约 +120–185KB** |

**建议**：`app.html` 的预算从 1.70MB 上调到约 **1.90MB**，`dist/app.html` 相应从 4.7MB 调到约 4.9MB。
**理由**：现在只剩约 31KB 余量，连 P0 都放不下；这些新增都是用户明确要求的功能，没有依赖误内联或资源误入库（预算本来就是防这类问题的护栏）。按记忆里的口径：功能第一，预算挡路就上调，并在提交信息里写明。

**性能**：
- 新贴图单边 ≤ 512px，按「这套房子已用」缓存，换户型时释放；
- 选择器的缩略图走现有的懒加载队列（IntersectionObserver + 分批），不预生成；
- 悬停预览只换材质引用，不重建几何，单帧完成。

## 7. 这份研究没有覆盖到的

- 没有做真实用户访谈；「房主常做的选择」依据的是行业常规规格和主流品牌的公开品类结构，不是一手数据。
- 程序化贴图做出来能有多像（洞石、花砖、墙纸）没有做原型验证，体积估算可能有 ±30% 的偏差。
- 「装修跟方案走」的数据设计只提了方向，没有评估对撤销、清单、导入导出的影响。
- 个人入口在这台机器上做 3D 截图会超时（已知的环境问题），3D 现状只在公开入口上看过。
