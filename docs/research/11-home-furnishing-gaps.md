# 11 · 「轻量但相对全面」的家庭布置预览器：gap 审计（2026-10-22）

> 触发：用户 2026-10-22 ——「作为一个虽然轻量级，但是需要相对全面的个人家庭布置设计预览器，还缺少什么重要功能，
> 有什么 UX 上面的 gaps。找出来然后一一实现」。同一条消息里点名了五件：插座被挡住时高亮、同轴电缆与网线口、
> **house 的多层与楼梯（「非常要命」）**、**地板品类与样式（「要命」）**、洗衣机 / 烘干机上下水口 + 通风管道口 + 抽油烟机管道口。
> 方法：逐个界面读代码 + 用户视角走一遍主流程（打开 → 建房 → 放东西 → 3D），对照 ADR-0006 的调性裁剪。

## 1. 愿景（这一轮要达到什么）

**问题**：MiniDen 现在对「一套公寓 + 现成家具目录」很顺手，但对 **house（多层、楼梯、洗衣房、通风口）**
和 **「东西摆在这里会不会挡住什么」** 这两类 homeowner 的核心问题几乎没有回答能力：

- 多层的房子画不出来（只有一个平面），楼梯无从表达；
- 地板只有一种（深烟熏橡木），换不了品类、看不出人字拼和大板砖的差别；
- 墙上的东西只有电源插座；网线口 / 同轴口（电视墙怎么摆）、洗衣机上下水、烘干机排风口、油烟机排风口、
  地面 / 墙面送风口都没有 —— 而这些恰恰决定了大件家电与家具**只能**放在哪里；
- 家具摆下去之后，挡住插座 / 送风口、挡住门开不了、穿进墙里，都不会提示。

**目标结果（从用户角度、可验证）**：

1. 从空白画布画出一栋两层的房子 + 一部楼梯，3D 里能看到上下两层叠在一起、上层楼板在楼梯处开洞，室内视角能从楼梯口看到另一层。
2. 用户点名的每一类点位都能放、2D 有图例、3D 有实物，被家具挡住的那一个在 2D 上高亮。
3. 点一个房间就能给它换地板（至少：木地板若干色 × 直铺 / 人字拼 / 鱼骨拼，瓷砖若干规格，石材、地毯、乙烯基、水泥），
   2D 能看出是哪种、3D 是真实尺度的贴图，并显示这个房间的面积。
4. 拖家具时能贴墙、看得到离墙多远；挡住门 / 插座 / 送风口、穿墙都有高亮。

**反目标（明确不做）**：拆墙改结构的工程判断、施工图（电路回路、水管走向、风管走向、承重、楼梯规范校核、
砖的切割排版）、细节装修（踢脚线 / 吊顶造型 / 楼梯踏步的前缘突出量 —— ADR-0006 原例）、建材下单。
**判据**：如果一件事回答的是「东西放哪 / 放不放得下 / 看起来怎样」，做；回答的是「怎么施工」，不做。

## 2. 现状盘点（读代码 + 走流程得出的事实）

| 面 | 现状 | 证据 |
|---|---|---|
| 楼层 | 一份户型 = 一个平面；没有楼层概念、没有楼梯实体 | `ProjectDoc` 无 levels；`buildStatic3D` 只建一层（地板 y=0、天花 y=CEIL_H） |
| 地板 | 整个户型一块 `ShapeGeometry` + 一张程序化深烟熏橡木贴图；2D 无地板表达 | `buildStatic3D` → `woodTexture()`（种子 1001） |
| 自包含户型的地板轮廓 | 墙体包围盒 +0.8ft 的**矩形**：L 形房子的地板伸到墙外 | `importedFloorPts()` |
| 房间 | 内置户型的房间名是常量；自包含户型读 `DOC.rooms`（只有导入时才有）；**界面里没有给房间命名的工具**，也没有面积 | `build2D` 房间标签分支 |
| 点位 | 只有电源插座（S14：普通 / USB / GFCI，墙面 / 台面 / 台柜） | `ProjectDoc.outlets` |
| 家具 ↔ 环境 | 只查「家具 ↔ 家具」重叠；不查穿墙、不查门扇扫过的区域、不查挡住插座 | `drawFurniture` 重叠检测 |
| 家具拖动 | 量化 0.05ft；**无贴墙吸附、无离墙距离提示** | `svg pointermove` 的 `move` 分支 |
| 家具离地 | 一律落地（`vSpan` = [0,h]，3D y=0）：壁挂电视、吊柜、挂画表达不了 | `vSpan` / `sync3D` |
| 目录 | 280 条，偏重儿童用品；**没有电视、衣柜、洗衣机 / 烘干机、冰箱（只有台面模块）、窗帘、绿植、挂画** | 目录分类统计 |
| 多选 | 无（一组餐桌椅只能一件件挪） | `selected` 是单个 uid |
| 清单导出 | 采购清单只能看，不能导出 / 复制 | `#placedList` |
| 层高 | `DOC.ceilingH` 存在但界面里改不了 | 无控件 |

## 3. Gap 清单与优先级

P0 = 用户点名；P1 = 审计发现、直接影响「放哪 / 放不放得下」；P2 = 有价值但可以晚一步。
状态在 `docs/roadmap.md` 的对应行里维护。

| # | Gap | 优先级 | 方案要点 | 路线图 |
|---|---|---|---|---|
| G1 | 插座 / 点位被家具挡住时高亮 | P0 | 墙面点位：家具占地覆盖它正前方、且家具顶高 ≥ 面板下沿 → 红色高亮；地面点位（送风口 / 地漏）：占地覆盖即算（地毯也算）；天花点位不判 | S15 |
| G2 | 同轴电缆口、网线口 | P0 | 点位家族扩展（与插座同一实体、同一工具） | S15 |
| G5 | 洗衣机上水 / 下水、地漏、烘干机排风口、送 / 回风口、油烟机排风口、燃气口、240V 大功率插座、开关 | P0 | 同上；新增**地面**与**天花**两种安装面（送风口在地上、油烟机管道口常在天花） | S15 |
| G4 | 地板品类与样式 + 房间命名与面积 | P0 | 「房间」工具：点一下房间内部 → 自动找出这个房间的轮廓（栅格泛洪 + 轮廓追踪，墙 / 窗 / 门洞 / 开口都算边界）→ 命名、看面积、选地板（品类 × 颜色 × 铺法 × 方向）。2D 淡色底纹，3D 真实尺度贴图 | S16 |
| G16 | 自包含户型的地板轮廓是矩形（L 形房子地板伸到墙外） | P1 | 同一套栅格：从外部泛洪，补集 = 室内 → 真实外轮廓 | S16 |
| G3 | 多层 + 楼梯 | P0 | 文档内楼层（ADR-0007）：一份户型 = 若干楼层，当前层的内容换进文档顶层（现有编辑代码不动）；家具带楼层标记；楼梯属于下层，上层楼板在楼梯处开洞；3D 娃娃屋显示本层及以下、室内显示全部；下层墙线可作参照 | S17 |
| G10 | 每层的图纸各自导入 | P1 | 导入确认框多一个选项：「导入为当前户型的新楼层」 | S17 |
| G11 | 层高改不了 | P1 | 楼层设置里改层高（楼层标高随之重排） | S17 |
| G6 | 拖家具没有贴墙吸附、看不到离墙多远 | P1 | 背靠墙 / 侧靠墙时磁吸贴齐（屏幕像素阈值），拖动中显示到最近墙面的距离标注 | S18 |
| G7 | 家具穿墙、挡住门扇不提示 | P1 | 穿墙 = 与墙体多边形相交 → 红；门扇扫过的扇形区域被占 → 门符号红 | S18 |
| G9 | 家具不能离地（壁挂电视 / 吊柜 / 挂画）；目录缺电视、衣柜、洗衣机、烘干机、冰箱、绿植、挂画、落地镜 | P1 | 检视面板「离地」；通用件目录（无价格、标准尺寸档位）+ 程序化建模（守建模三律） | S19 |
| G12 | 多选 | P2 | Shift+点选 / 框选 → 整组移动、旋转、复制、删除 | S20 |
| G13 | 采购清单导出 | P2 | 导出 CSV / 复制为文本（含楼层、数量、单价、链接） | S20 |
| G14 | 窗帘 | P2 | 窗实体上的可选窗帘（样式 / 颜色），2D 窗内侧一条波浪线，3D 布帘 | S21 |
| G15 | 墙面颜色 | P2 | 按房间设墙漆颜色（只影响 3D 墙面材质） | S21 |

**刻意排除**：外立面与屋顶（不是「布置」）、户外庭院景观、楼梯踏步细节与规范校核、电路 / 水路 / 风路的走向、
地砖切割排版与损耗计算、灯光照度计算（已有昼夜与光追，足够回答「亮不亮」）。

## 4. 实现顺序（依赖序）

S15 点位家族 + 挡住高亮 → S16 房间与地板（栅格区域模块是 S17 楼板开洞与外轮廓的前置）→ S17 多层与楼梯 →
S18 家具贴墙 / 距离提示 / 穿墙与门扇遮挡 → S19 离地 + 通用件目录 → S20 多选 + 清单导出 → S21 窗帘 + 墙色。

每一项的设计、验证计划与门禁写在 `docs/design/home-v2.md`；多层的架构决定在 ADR-0007。
