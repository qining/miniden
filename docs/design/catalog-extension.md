# 目录扩展协议（S10）

> 一句话：**把一批商品装进家具目录，不需要改 `app.html`。**
> 目录条目是数据（JSON），建模代码是函数源码（字符串），两者打包成一个 `.json` 文件，
> 用户在界面里选文件 → 确认 → 目录里就多了一组可挑、可摆、可计价、可撤销的条目。

这是 ADR-0006「扩展**代码优先**」的落地：运行时零 AI、零网络、零服务端。
`add-catalog-item` skill 是**交付物**（教人怎么写包），不是运行时依赖。
规模依据 = R8-5K（目录规划规模 5,000 件，用户决策 2026-09-17）。

---

## 1. 三层结构

| 层 | 位置 | 角色 |
|---|---|---|
| **条目 schema** | `src/catalog/schema.ts` | 一条目录条目的字段定义 + 校验 + 归一化（内置目录与外部包**共用同一份**） |
| **包协议** | `src/catalog/packs.ts` | 包文档结构、包级/条目级校验、模型源码编译、与内置目录合并、注册表与持久化 |
| **应用接线** | `app.html` | 「工具 ⌄」里的导入/移除按钮、确认弹窗、目录卡片标记、幽灵占位、存储门面 |

编译产物 `<script id="miniden-catalog">`（由 `scripts/build-catalog.mjs` 生成）把
`src/catalog/` 的 schema + 内置目录 + 模型注册表灌进页面，`window.MINIDEN_CATALOG` 是唯一入口。
`build.mjs` 每次构建都断言**嵌入块与 `src/catalog/` 的最新编译逐字节一致**（旧编译产物 = 过期副本）。

## 2. 包文件格式

```jsonc
{
  "pack": {
    "id": "demo-side-tables",     // 全局唯一；加载后不可变（改内容请换 id）
    "name": "示例目录包 · 三只边几",
    "version": 1,
    "source": "自建示例（无商品来源）",   // 来源说明，确认弹窗里会显示
    "license": "示例数据，仅供演示协议"
  },
  "entries": [
    { "id": "demo-st-0", "cat": "茶几 / 边几", "name": "示例边几 · 通用回退建模",
      "w": 45, "d": 45, "h": 55, "kind": "sideTable", "price": 39, "priceCA": 52,
      "color": "#c9b28c", "wood": "birch", "url": "", "note": "没有 model → 用 kind 通用建模" }
  ],
  "models": {
    // key = 条目的 model 值；值 = 一个函数表达式源码，签名 (C) => { ... }
    "demo-tray": "(C) => { const cm = C.cm; C.cyl(cm(19), cm(19), cm(2.6), C.m.wood('birch'), 0, 0, 0, 28); return C.g; }"
  }
}
```

`entries` 与 `models` 都可选，但至少有一个。示例：`examples/packs/demo-side-tables.json`。

### 上限（棘轮，不是建议）

| 上限 | 值 | 为什么 |
|---|---|---|
| 单包条目数 | 2000 | 5,000 件规模 = 少数几个包，而不是一万个碎片 |
| 单包模型数 | 500 | 模型源码是**要编译并驻留内存**的代码 |
| 单个模型源码 | 60,000 字符 | 超过这个量级的模型代码应该拆件，不该塞在一个函数里 |
| 整包模型源码 | 400,000 字符 | 包体积上限的代理指标 |
| 同时加载的包 | 32 | 注册表 + 每包一个存储键，再多就没有可管理的边界 |

## 3. 校验：两层，不连坐

`validatePack()` 返回 `PackCheck = { pack?, issues, entryIssues, ok }`：

- **包级错误**（`issues`）→ **整个包拒收**：包 id 非法/撞内置/撞已加载、缺 `entries` 与 `models`、
  超限、`models` 不是对象、模型源码不是字符串。这些是「这个包本身不合法」，
  没有「只加载一半」的意义。
- **条目级错误**（`entryIssues`）→ **只丢那几条**：一条坏条目不连坐整包。
  确认弹窗逐条列出「哪条、哪个字段、为什么」，用户仍然可以加载剩下的好条目。

条目级校验（`validateEntry`）要点：

| 规则 | 判据 |
|---|---|
| 尺寸 | `w/d/h` 必须是数字、落在 `1..1200` cm（`ENTRY_MIN_CM`/`ENTRY_MAX_CM`） |
| 价格 | `price`/`priceCA` 是数字、`0..100000`；**没有价格 = 提醒**（warning），除非显式写 `noPrice: true` |
| 币种字段 | `caNA` 布尔；`caVar` 布尔**或**字符串（≤240 字）——两种写法都有消费端 |
| 颜色 | `#rgb` / `#rrggbb`；旧别名 `col2` 自动归一化成 `color2` |
| `kind` | 必须是已知 kind（决定 2D 图例、通用回退建模、材质分类、碰撞高度） |
| 灯具 | `cct` 1500–7000K、`lum` 1–10000 lm；`dimmable` 布尔 |
| 未知字段 | 保留但不消费 → warning（不拒收，前向兼容） |
| 撞内置 id | 条目级 warning「与内置目录撞 id（内置优先，这条不会生效）」 |

**「缺价格 = 提醒，显式 `noPrice` = 意图」** 是刻意的：目录里固定灯具（公寓自带）与
套件的不同拼法本来就没有独立售价，沉默地漏掉价格才是错误。

## 4. 建模代码契约

`models[key]` 的值是**一个函数表达式**的源码。编译方式：

```js
new Function('"use strict";return (' + src + ');')()   // 只接受一个函数表达式，不执行额外语句
```

编译失败 → 该条目退回 `kind` 的通用回退建模，并在确认弹窗与提交提示里如实报数
（「N 个建模代码解析失败，这些条目会用通用回退建模」）。**不静默**。

函数签名 `(C) => { ... ; return C.g; }`，`C` 就是内置模型用的同一个 `modelCtx`：

| 类别 | 提供 |
|---|---|
| 尺寸 | `C.w/d/h`（已换算成英尺）、`C.cm(x)`（cm→英尺）、`C.seatH` |
| 配色/实例 | `C.col`、`C.col2`、`C.spec`、`C.it`、`C.cct`、`C.lum` |
| 材质 | `C.M(color, {rough, metal, clear, clearRough, sheen, sheenColor, fabric, leather, plastic, wood, envI, flat})`、`C.m.{wood, fab, chrome, steel, black, white, plastic, leather, glass}` |
| 几何 | `C.box` `C.rb` `C.cyl` `C.tube` `C.sph` `C.torus` `C.lathe` `C.ext(pts, depth, mat, x,y,z, plane, bevel)` |
| 软包/五金 | `C.cushion` `C.legT` `C.bar` `C.knob` `C.caster` |
| 阵列 | `C.rep(n, fn)` |
| 底层 | `C.g`（要返回的 Group）、`C.THREE` |

**外部代码不豁免内置的三条硬约束**（AGENTS §5.4.7）：

1. **占地诚实**：包围盒对 `spec.w/d/h` 的填充率落在 **92%–102%**；
2. **所有部件贴地**：`bbox.min.y > -0.02`；
3. **水平重心归零**：原点 = 占地中心（2D 图例与碰撞都假定这一点）。

这三条由 bench 断言 `cat-pack-model-honours-footprint` 守着（对包里的每个模型逐条量）。
写包的人自己的验收：`python3 .claude/skills/add-catalog-item/check-item.py <条目id>`。

## 5. 合并规则

`mergeCatalog(builtin, packs)`：

- **内置目录永远赢**。撞 id 的包条目被丢弃并记进 `conflicts`（`reason` 说明被谁覆盖）。
  理由：内置条目带着已验收的建模代码与已核对的商品数据，外部包不能把它换掉。
  想改内置件 = 改 `src/catalog/`，走代码评审，不是走一个 JSON 文件。
- 包内撞 id → 保留第一条，其余丢弃（条目级 error）。
- 包与包之间撞 id → 先加载的赢，后来的记进 `conflicts`。
- 合并结果带 `sourcePack: <packId>`，目录卡片上显示「包」标记，采购清单能按包统计。

`modelFor(key)` = `MODELS[key] || packModelFns.get(key)`：**内置模型优先**，
包模型只在内置没有时生效（撞名的包模型被跳过，`packShadowedModels()` 报数）。

## 6. 持久化与多户型

- 注册表 `planner_packs_v1`（`{v:1, packs:[{id, name, version, source, entries, models, loadedAt}]}`）
  只存元数据；包内容本身存在 `planner_pack:<id>`。
- 走 E10 存储门面（IndexedDB 主存 + localStorage 镜像）。**包键不在户型存档的门面闸门里**：
  包是「这台浏览器的目录扩展」，不是「这份户型的存档」，所以 `planArchiveUnknown` 不拦它。
- 启动时 `loadPacksFromStore()` 读注册表并装载；**不强制展开目录分组**
  （否则每次刷新都覆盖用户的展开状态，AGENTS 轮㉑）。
- 包与户型无关：切户型不换目录，换浏览器/清数据会丢包（所以确认弹窗提示「包文件是你自己选的」）。

## 7. 信任边界（必须如实写在界面上）

包里的建模代码是**在用户本机本地执行的 JavaScript**。这个应用不联网、不存凭据、
包文件是用户自己选的 —— 所以唯一的防线是「只加载你信任来源的包」。
确认弹窗必须把这件事说清楚（`#packTrust`），并且把包名/id/版本/来源/条目数/模型数全部摊开。

协议侧的机械防线：

- 只接受「一个函数表达式」，外层括号 + 立即取回，不执行任何额外语句；
- 严格模式；
- 上面那张上限表（体积、数量）；
- 编译失败不静默、合并冲突不静默、坏条目不静默。

## 8. 移除包 = 两步确认，之后是「幽灵件」

移除一个包会让**已经摆在布局里、用它的条目**的家具失去规格（尺寸、价格、模型）。
这不是一句撤销能兑的，所以按钮是两步确认（第一次点击变警告色 + 提示「再点一次确认」，
并说明布局里有几件用的是它）。

移除之后：

- 布局里那件**还在**（不删用户摆好的东西）；
- `itemSpec()` 仍然返回 `null`（价格合计、按包计数依赖这一点）；
- 但**显示层必须诚实**：2D 画一个灰色虚线方块 + `?`（可点、可选、可删），
  3D 画一个 40cm 灰色占位盒，检视面板写「目录里没有这件（仍在布局里）」、价格显示「—」。

这条是轮㉘ 抓出来的真 bug：`drawFurniture()` 的选中分支直接读 `spec.w`，
`spec` 是 `undefined` 时整个 2D 家具层抛异常停摆（AGENTS §5.1）。

## 9. CLI（没有 AI 也能验收）

```bash
npm run catalog:build      # src/catalog/ → 编译产物 + 灌入 app.html 的 <script id="miniden-catalog">
npm run catalog:check      # 内置目录体检（--json 出机器可读结果）
node scripts/catalog-check.mjs examples/packs/demo-side-tables.json   # 体检一个包文件
```

CLI 的判据**故意比界面严**：界面可以「拒掉坏条目、加载好条目」，
CLI 的语义是「体检这个包」——坏条目也算 error（退出码 1），这样 CI 与作者能一眼看出问题。

内置目录当前状态：**280 条 / 146 个模型函数 / 0 error / 0 warning**。

## 11. Phase 2（已落地 2026-10-13）：5,000 件规模的四条口径

R8-5K 的规模要求（5,000 件 / 12.5MB 模型源码 / 5,000 张缩略图）在 Phase 1 的实现里会在启动时
全部编译、全部驻留、全部缓存。Phase 2 把「规模」变成可执行、可测的四条口径。

### 11.1 模型懒编译 + LRU 驻留（`src/catalog/models.ts`）

包模型源码存在包文档里（主存），用到哪个才编译哪个：

| 常量 | 值 | 依据 |
|---|---|---|
| `MAX_RESIDENT_MODELS` | 400 | 实测一个模型函数 + 它的闭包源码 ≈ 3KB → 上限约 1.2MB 驻留 |

- `get(key)`：未编译 → 从索引里的源码编译 → 装进缓存；命中 → 挪到最近使用端（Map 插入顺序当 LRU 用）。
- **坏源码只编译一次**（`failures` 表）：否则每次建模都把同一段坏源码重新编译一遍。
- **导入路径仍然编译一次并 seed 进缓存**：确认框里那句「解析失败 N 个」必须是真的（轮㉙ 的不变量）。
- `setIndex(next)` 按「源码是否同一份」淘汰驻留项：同一个 model 名换了内容绝不能继续用旧函数。
- `dropPack(packId)` 清掉那个包的全部驻留项与失败记录。

### 11.2 内容指纹 = 来源核验的第一层（`PACK_SCHEMA` 1 → 2）

注册表元数据带 16 位内容指纹（规范化 JSON：递归排序对象键 → FNV-1a）。装载时比对：

**对不上 → 不加载、不删存储内容、不删注册表，并如实告诉用户怎么办（重新导入那个包文件）。**
这与 §10 的「读不到 ≠ 不存在」是同一条红线：能救的东西不许顺手删掉。

旧注册表（v1，没有这个字段）不伪造指纹，`digest:null`，第一次重新导入时补上。
格式不对的指纹字符串一律当没有（不能信一个自称是指纹的东西）。

### 11.3 包升级路径（`CATPACK.packUpdateDecision`）

同 id 不再是「无条件整包替换」：

| 情况 | 决定 | 界面说什么 |
|---|---|---|
| 没加载过 | `add` | 正常确认框 |
| 更高版本 | `update` | 确认框写「更新已加载的这份包：版本 1 → 2（条目 3 → 4，建模代码 2 → 2）」 |
| 更低版本 | `reject` | 入口就拒：「版本 2 已经加载了，这份是版本 1：先移除再导入」 |
| 同版本 + 同指纹 | `same` | 入口就拒（不变更）：「已经加载了…没改动任何东西」 |
| 同版本 + 不同指纹 | `reject` | 入口就拒：「改内容请把 version 提高到 3 以上再导入」 |
| 旧记录没有指纹 | `update` | 允许替换并补上指纹 |

判据在**入口**就跑（与包上限同一条红线）：不能「先弹确认框、用户点了才说不能装」。

**启动装载不走这条判据**：注册表里那份元数据就是本份包的记录，走 `packUpdateDecision`
必然得到 `same → 不重复替换` → 包永远加载不上。装载路径显式传 `decision:{action:'load'}`。

### 11.4 两条预算

| 预算 | 值 | 实测依据 | 超了怎么办 |
|---|---|---|---|
| 缩略图缓存 `_thumbCache` | 300 张（LRU） | 一张 320×240 的 PNG dataURL ≈ 60KB → 5,000 件 = 286MB；300 张 ≈ 18MB | 淘汰最久没用过的（它会重画） |
| 单件三角形 `MAX_ITEM_TRI` | 40,000 | 目录里最重的内置件 12 三角形；包建模只能在用户机器上第一次用到时实测 | 记下来，在「工具 ⌄ → 目录包」里如实列出（不许静默降质） |
| 场景三角形 `MAX_SCENE_TRI` | 1,200,000 | 满家具客厅 22 件 ≈ 10 万三角形；光追压力测试 52 件 ≈ 24.6 万 | 提你一次（说清哪几件最重），**绝不静默删件** |

**目录规模与场景负载解耦**：目录多 300 条，场景一个三角形都不多（断言 `cat30-catalog-size-not-scene-load`，实测 21,209 → 21,209）。

`sceneBudgetCheck(budgetOverride?)` 的 `budgetOverride` 参数只为可测性存在
（1,200,000 个三角形在 headless bench 里根本建不出来）——与 §5.5 把 `ptPickGrid` 纯函数化
是同一条理由：真实规模在测试环境里测不到，就必须把决策做成可注入的纯函数。

### 11.5 还没做的

- **包签名 / 来源证明**：现在只有内容指纹（能查出「存下来的内容与导入时不一致」），
  没有「这个包是谁写的」的证明。信任仍然靠用户自己选文件（确认框里明说了）。
- **包之间的依赖**：包不能引用另一个包的模型。真需要时再加 `requires`，别提前设计。
- **缩略图预生成 / 磁盘缓存**：仍然是零预生成（渲染一次缓存一次）。5,000 件时
  「第一次滚到就有一次渲染延迟」会明显，届时考虑把缩略图存进主存。
- **目录本体搬出 `app.html`**：`CATALOG` 仍是 app.html 里的数组（85KB 级）。
  搬出去是 E2/E3 的模块化工作，不是本协议的缺口。
