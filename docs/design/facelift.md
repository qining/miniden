## 0. 怎么读这份规格

### 0.1 给工程组的三条约定

1. **id 和处理器尽量不动**：现有元素一律保留 id，只搬位置（`appendChild` 搬 DOM，id 和监听器跟着走）、改文字、改样式。确实要新增的控件，本文给出建议 id，并在去向表里标成 **新**。
2. **「影子控件」模式**：把 `<select>` 或循环按钮换成色块网格、分段控件时，**原控件留在 DOM 里，只是隐藏**（`hidden` 属性或 `.vh` 视觉隐藏）。它继续当状态源和处理器入口；新视图只做两件事：点击时给原控件赋值并派发 `change`（循环按钮就调用 `.click()`），刷新时读原控件的值来画选中态。这样处理器一行不改，测试台里 `$('#rmFloor').value=…; dispatchEvent(change)` 这类断言照样能跑。**只有 `textContent` 断言需要按新文案改写。**
3. **`#calib` 视图（`body.calib`）冻结**：§8 列出了 calib 下需要隐藏的每一个新元素，新增 CSS 时一并加上。

## 1. 设计原则（本规格的裁判标准）

1. **一个分区 = 一种意图**：顶栏三分区「摆家具｜装修｜改户型」。分区决定**左栏放什么**、**画布上点一下是什么意思**、**检视面板显示哪些属性**。
2. **选中什么，右边就显示什么**：所有属性都出现在右侧「检视」标签里，顶部工具条只放工具。
3. **琥珀色实心每屏只出现一次**，留给主动作（「完成」「用示例户型开始」「画外墙」）。「当前选中的」用中性亮底加琥珀细描边或下划线表示。
4. **三个视图共用一套顶栏**：切 2D、3D、室内时顶栏一个像素都不动；跟视图有关的东西（量尺寸、场景）放到画布右上角的浮层里。
5. **低频、危险、设置级的东西往下沉**：放进 文件 ▾、⚙、?、⋯、面包屑下拉；危险操作一律要点两下确认，或者能撤销并明说「可以撤销」。

### 5.6 色块网格细则

- **地板**：4 列正方形（检视面板 ≥ 256px 时一格约 58px）；缩略图用 `floorTexture(id)` 的 canvas 缩到 112×112，转成 dataURL 缓存起来（按 2 倍屏取），**颜色必须是真实色相**（不要套暗色主题叠加）。第一格「跟全屋」用虚线框、灰字。按 `FLOOR_CATS` 分组，组名一行 11px。状态：默认 1px 白 12% 描边 → 悬停描边 `--muted` → 选中 2px 面板色间隔 + 2px 琥珀外环 + 右上角 ✓ 徽标 → 禁用 `opacity:.38`。
- **墙色**：7 列圆角方块；第一格「白墙」，接着 12 个 `PAINT_PRESETS`，最后一格彩虹色「自定义…」（打开 `#rmWallC`）。如果当前值是自定义颜色，最后一格就画成那个颜色并带选中态。
- **窗框**：一行 5 个 24×24 的方块，选中态同上。
- 键盘：方向键在网格里移动焦点，空格 / 回车选中（`role="radiogroup"`，每格 `role="radio"` + `aria-checked`）。

## 8. 约束遵守说明

### 8.1 `#calib`（`body.calib`）

校准截图是 2400×1500 窗口下按固定偏移裁出来的（AGENTS §1.1：`sips -c 1360 1674 --cropOffset 72 369`，也就是**第 72–1432 行、第 369–2043 列**）。在 calib 下，画布 `#stage` 的位置是 x=270、y=49、宽 = 窗宽 − 520（实测 1440 窗口：`{x:270, y:49, w:920}`）。所以：

1. **顶栏高度必须是 49px**：新规则把 `#topbar{height:49px}` 写死，calib 和非 calib 是同一个高度（原来就是 8+32+8+1）。顶栏里的内容在 calib 下可以变（它在裁剪框上面，第 0–48 行），但为了省心建议：
   ```css
   body.calib #modeSeg, body.calib #saveState, body.calib #btnSettings, body.calib #btnHelp{display:none !important;}
   ```
   （`#btnMore` `#measSeg` 本来就有 calib 隐藏规则，保留。）
2. **模式条在 calib 下永远不出现**（`#btnWallEdit` 在 CALIB 下直接 alert 返回，不变）。保险起见：`body.calib #wallbar{display:none !important;}`。
3. **侧栏宽度锁定不变**：`body.calib #catalog{width:270px}` `#props{width:250px; padding:12px}` 保留；新的标签行 `#propsTabs` 在 calib 下隐藏（`body.calib #propsTabs{display:none !important}`，跟原来 `.panelHead` 的处理一样），检视的内容照旧显示（它在第 2150 列以外，不在裁剪框里）。`#decoPanel` 在 calib 下不会出现（进不了装修），加一条 `display:none` 兜底。
4. **画布里的新浮层全部隐藏**——它们会落进裁剪框：
   ```css
   body.calib #crumbs, body.calib #stageTR, body.calib #emptyCard, body.calib #modeNote,
   body.calib .menu{display:none !important;}
   ```
   `#levelBar` 和 `#layBar` 搬进 `#crumbs` 后跟着一起隐藏（原来 `levelBarUI()` 在 CALIB 下就隐藏）。`#stageTR` 里的 `#measSeg` 本来就是 calib 隐藏。
5. **`#hint` / `#totals`**：它们在第 1432 行以下（底边距画布底 10–12px，高度 ≤ 58px），本来就不在裁剪框里；新的 `max-width` 和芯片样式在 calib 下**不改**也行，建议加 `body.calib #totals{height:auto}` 之类的规则保持旧尺寸，免得提示行变高越过第 1432 行。**最后以 md5 实测为准。**
6. **2D 绘制改动全部门控 `!CALIB`**：地板真实色相、房间标签光晕、3000K 标注、装修选中房间的描边、清单相关的画布标注。`.roomlabel` 的 CSS 改动不能直接改那条规则（calib 也用它），要加一个新的 class，或者写成 `body:not(.calib) .roomlabel{…}`。
7. `applyPanels()` 在 CALIB 下 return 不变；改户型自动收起左栏的逻辑也要先判断 `CALIB`（虽然 calib 进不了改户型，加一行守卫就行）。

验收：每一步落地后，从仓库根目录打开 `planner.html#calib`，按 AGENTS §1.1 截图并算 md5，必须等于 `1ac26921871db50ef1c055674c10e6e7`。

### 8.2 其他约束

- **单文件**：全部 CSS / JS 写进 `app.html`；原型 `work/ux/facelift-mock.html` 只是参考，不要引用它。
- **暗色主题**：只新增角色变量，不改现有变量的值（§5.1）；2D 绘图调色（`--drw-*`）不动。
- **黄金截图（ui-gate）**：F1–F5 每一步都会改变截图，要显式重拍并记录差异（§5.4）。
- **断言口径**：去向表里「新文案」那一列，就是需要改写的 `textContent` 断言清单（例：`#btnWallEdit` 的文字「编辑墙体」→「改户型」，`#btnMore`「工具 ⌄」→「文件 ▾」，`#pTitle`「未选中家具」→「还没选中东西」）。

## 10. 与 §5 / 审阅报告的分歧（以及理由）

| # | 本规格的做法 | §5 / 审阅的说法 | 理由 |
|---|---|---|---|
| 1 | 摆家具里**只有什么都没选时**点空地板才出房间摘要卡，卡上有按钮去装修；**不**自动切分区 | §5.3：点地板 = 选中这个房间，并打开「装修」检视面板里的地板 | 点空地板是现在「取消选中家具」的手势，用得非常多；如果每次都选中房间（甚至切分区），会和取消选中打架。两段式（先取消，再点才出摘要）两边都不耽误 |
| 2 | 「放洁具」「画台面」**只在装修**（「房子自带」）；改户型的「更多 ▾」里只有插座与水电点位 | §5 F1 把台面同时列在「改户型 · 更多 ▾」和「装修」两处 | 一个工具只放一个家。台面和洁具是「房子自带的外观和设施」（X23 的逻辑），房主会在装修里找；两处都放，会让同一个工具有两套上下文 |
| 3 | `#wDelete` 放进**检视面板底部**（「删除这扇窗 Del」）；⋯ 里只放「恢复原始户型」和「按选中这段缩放整张图」 | §5 F1：重置内置、整图缩放、删除所选都收进 ⋯ | 删除是**对象级**操作，和家具检视里的「删除」同一个位置，一致性更好；⋯ 留给**户型级**、低频、危险的操作。Delete 键不变 |
| 4 | 模式条**只放工具**；「下一个要画的」参数（窗宽、梯宽、洁具类型等）放进检视面板的「下一个」卡片 | §2 草图 / X04：顶部工具条放工具 +「下一个要画的」参数 | 这样 1280 下工具条保证单行（X06 的根源就是参数挤在工具条里）；所有参数都在同一个地方，选中前、选中后控件也不会换位置。代价是：画窗前要往右边看一眼（卡片标题会写「窗 · 下一扇」） |
| 5 | 「拍一张效果图」**两处都有**：文件 ▾（代理）和室内视角的「场景 ▾」底部（`#btnPT` 本体） | §5 F5：「光追渲染」改「拍效果图」，进「导出 ▾」或场景浮层 | 文件菜单方便发现；场景浮层是拍之前调灯光、时间的地方，紧挨着「拍」最顺手。只有一个本体，另一个是代理 |
| 6 | 窗帘：房间区块写「一次给这个房间的每一扇窗配上」，单扇窗写「只改这一扇」；**没有**「跟房间」的继承选项 | X24：以房间为主，单扇窗只放「例外」 | 数据里窗帘是按扇存的，没有继承关系；写「跟房间」会骗人（改房间窗帘时会覆盖所有窗）。如果以后要做真正的继承，需要改数据（记为候选） |
| 7 | 用户可见处不再出现「内置」：公开入口叫「示例户型」，个人入口直接写户型名 | 审阅报告和 §5 都沿用「内置户型」的说法 | 「内置」是开发者视角。个人入口的那份是用户自己的房子，叫「示例」也不对，所以按入口区分 |
| 8 | 改户型时**左栏收起**（不是换成工具库） | §5 F1：两侧面板在改户型里不再整列灰着占地方（没说换成什么）；X22 两种方案都提了 | 改户型的工具在模式条上，参数在检视里，左栏已经没有要放的内容了；收起能给画布多出约 300px，画墙正需要 |
| 9 | 「场景 ▾」和「量尺寸」搬到画布右上，放在 F3 里做（§5 把场景浮层列在 F5） | §5 F5 | 它们和顶栏改造是同一次手术；拆开做的话，顶栏要改两次，断言也要改两次（§5.1 自己的原则） |
| 10 | 原型 `#furn` 状态在 2D 地板上试了一层 20% 的暗化 | §5 F5：2D 地板按真实色相 | 只是给 UX 复核的一个选项（家具在地板上更跳出来）；规格的缺省是 F5 的真实色相 |

没有采纳、和 §5 保持一致的：同款不同色合并成一张卡（X36）、固定灯具 / 洁具统一进构件库（X23）、3D 射线点选建筑构件。原型里的清单也**只按目录 id 合并**。
